# Local coding agents, remote Kaggle inference

`home/agents.nix` imports `home/kaggle-llm.nix` in the existing shared Home
Manager configuration. It packages two commands with Python, pass, and the
same Claude Code package already used by this flake. No new agent, Nix input,
local tunnel, Kaggle CLI, or model download is needed for the notebook route.
Codex and ordinary `claude` launches retain their existing configuration.

## Runtime credentials

Create the file yourself, outside this repository and the Nix store:

```bash
install -d -m 700 ~/.config/kaggle-llm
(umask 077; touch ~/.config/kaggle-llm/env)
chmod 600 ~/.config/kaggle-llm/env
$EDITOR ~/.config/kaggle-llm/env
```

Example contents (replace the placeholders in your editor):

```sh
KAGGLE_LLM_URL="https://YOUR-SESSION.trycloudflare.com/v1"
KAGGLE_LLM_PASS_ENTRY="kaggle-llm/api-key"
KAGGLE_LLM_MODEL="qwen3.8-27b"
```

Store the notebook's generated API key through the existing encrypted store:

```bash
pass insert kaggle-llm/api-key
```

Alternatively put `KAGGLE_LLM_API_KEY="..."` in the private env file. Environment
variables with these names override file values; exported URL/key variables
work too. A literal API key takes precedence over a pass entry. The file accepts
quoted literal assignments, optional `export`, blank lines and comments; no
shell commands, substitutions or interpolation. The wrapper requires HTTPS,
accepts the root URL or `/v1`, and leaves the working directory unchanged.

```bash
kaggle-code-status
cd ~/some-repo
kaggle-code
# Normal provider again:
claude
```

Update the URL and key after each Kaggle restart; no rebuild is required.
Already running agents retain their old endpoint: restart them after rotation.
No credentials are passed as command-line arguments or generated by Nix.
Provider variables are scoped to the launched process. Anthropic Bearer auth is
used; default main/subagent model aliases are mapped to the served model.
Existing local tools, MCP configuration, and permission settings still apply.
Do not pass a different `--model`/`--settings` unless intentionally overriding
this selection.

## Kaggle server (upstream checked 2026-10-09)

Use the [official Qwen notebook](https://www.kaggle.com/code/rahim3/qwen3-8-27b-bf16-on-kaggle-tpu-130-tok-s-api),
via **Copy & Edit**, rather than uploading any development repository.

1. Verify your Kaggle account and enable TPU access in account Settings.
2. In notebook Session options select **TPU VM v5e-8** and **Internet ON**.
3. Check Add Input includes `rahim3/qwen3-8-27b-bf16` and
   `rahim3/qwen38-tpu-env-v5e8` (the notebook's first cell lists them).
4. Start with the shipped config: `max_model_len=262144`, `max_num_seqs=4`,
   `mtp_tokens=3`, `reasoning_effort_default="xhigh"`. Keep `api_key` empty:
   the script generates a random key and passes it to vLLM authentication.
   Keep `ntfy_topic` empty: configuring it publishes endpoint credentials to
   that notification service. For coding without screenshots, optionally set
   `text_only=true`. For a shorter session set `keepalive_min=120`.
5. Run cells top to bottom. Leave the final server cell running. Wait for
   **READY**, not just the early tunnel URL. Copy its endpoint and key into
   your runtime configuration. Do not publish notebook outputs containing keys.
6. Run `kaggle-code-status` locally. Stop the Kaggle session when finished.

The [kernel](https://github.com/ARahim3/kaggle-tpu-lab/blob/main/qwen38-27b/kernel/serve_qwen38.py)
reads overrides from `serve_config.json`. If the notebook config needs changing,
edit its existing configuration cell before running the server. For structured
output crashes with MTP enabled, upstream advises `async_scheduling=false`.
Do not replace the patched serving recipe with stock vllm-tpu: the bundled MTP
rollback patch fixes output corruption.

The [Qwen recipe](https://github.com/ARahim3/kaggle-tpu-lab/tree/main/qwen38-27b)
currently supports Qwen3.8-27B bf16. It is the practical Qwen choice for several
agents; begin with three or four sessions. For higher concurrency upstream
suggests 131072 context, 16 sequences, and MTP disabled, at the cost of context
and potentially extra compilation. Throughput figures are upstream measurements,
not locally reproduced. Qwen prefix caching is currently disabled despite the
repository headline, so every agent turn re-prefills its context.

The other current recipe is
[GLM-5.3-Flash](https://github.com/ARahim3/kaggle-tpu-lab/tree/main/glm53-flash),
a quantized 320B MoE with a custom JAX engine. It is a quality-oriented alternative,
but the project supplies no comparative coding benchmark establishing a winner;
its full-context limit is three concurrent streams, with bounded queueing.
Use its separate official notebook if you choose it and set `KAGGLE_LLM_MODEL`
to the model ID in its READY banner. This wrapper is not tied to Qwen weights.

## Independent worktrees

From your local repository:

```bash
git worktree add -b agent-1 ../repo-agent-1 HEAD
git worktree add -b agent-2 ../repo-agent-2 HEAD
git worktree add -b agent-3 ../repo-agent-3 HEAD
# Separate terminals:
(cd ../repo-agent-1 && kaggle-code)
(cd ../repo-agent-2 && kaggle-code)
(cd ../repo-agent-3 && kaggle-code)
```

Each agent has its own files and process, sharing only the inference endpoint
(and git object database). Assign separate tasks/branches; review and integrate
commits yourself. Use separate build output paths/ports when tests need them.
No worktree helper is necessary.

## End-to-end smoke test

```bash
kaggle-code-status
mkdir -p /tmp/kaggle-agent-smoke
cd /tmp/kaggle-agent-smoke
git init
printf 'local-only marker\n' > marker.txt
kaggle-code
```

Ask: “Read marker.txt using your local file tool. Create answer.txt containing
its text reversed. Run a local shell command to print pwd and answer.txt.
Do not use MCP or web tools.” Approve local tools if prompted. Then inspect
`git diff --no-index /dev/null answer.txt` and the notebook's inference logs.
Authenticated model discovery verifies the configured model ID; a successful
agent turn plus local file/shell results verifies the complete path. No live
Kaggle endpoint was available during implementation, so this test must be run
after starting your session.

The repository stays local, but prompts, source excerpts, tool results and
possibly screenshots sent as model context are visible remotely to the server
and tunnel infrastructure. Existing MCP servers may independently send data to
other services. Keep secrets out of agent context; local credentials remain
readable to processes running as your user, so file permissions are not an
agent sandbox. A random tunnel URL is not authentication: retain API-key checks.

## Validation and activation

```bash
nix flake check --no-build path:$PWD
nix build --no-link path:$PWD#nixosConfigurations.nixos.config.system.build.toplevel
# Only when ready to activate (implementation never runs this):
sudo nixos-rebuild switch --flake .#nixos
```

Use `desktop` instead of `nixos` on that host. `path:` includes new, unstaged
module files during review; after they are tracked the usual `.#host` works.
